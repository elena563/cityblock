### SockDB

A _sock(et)_ drawer, but for JSON  
aka hopefully the first and last custom db I'll ever build

SockDB is a lightweight, schema-free document database built for this project. It stores JSON documents grouped into named collections, and exposes its interface over a raw TCP socket using a custom text protocol. See [TCP.md](./database/TCP.md) for the full protocol and command reference.

### Data model

- Collections are schema-free: documents in the same collection can have different shapes.
- Documents support deep nesting with no enforced limit - a document can embed arrays, nested objects, and further nested objects at any depth.
- Document IDs are UUID v4 strings, generated by the server at insert time and immutable thereafter.
- The path structure has two levels: `/collection` and `/collection/id`.

### Persistence

Each collection is stored as a separate JSON file under `resources/`. Every write operation triggers a synchronous, synchronized flush to disk. On startup, `FileManager` reads all `.json` files from `resources/` and pre-loads them into memory.

### Structure

| Class | Responsibility |
|---|---|
| `Main.java` | Entry point, starts the TCP server |
| `Database.java` | In-memory store, command handling |
| `FileManager.java` | Reads and writes collection files to disk |

Internal storage uses a `ConcurrentHashMap<String, ConcurrentHashMap<String, String>>`, where the outer key is the collection name, the inner key is the document UUID, and the value is the document serialized as a JSON string.

**Package:** `com.cityblock.sockdb`


## Project Execution

### Database

The database is a simple Java application. The following Maven commands can be used:

* `mvn clean`: to clean the folder of temporary files,
* `mvn compile`: to compile the application,
* `mvn exec:java`: to start the application (assuming the main class is `Main.java`). It listens on the address `localhost` on port `3030`.
