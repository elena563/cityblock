# SockDB - TCP Protocol

SockDB is a lightweight, schema-free document database exposed over a raw TCP socket using a custom text-based protocol. Each document is stored as a JSON object inside a named collection, and identified by a UUID v4 generated at insert time.

## Connection

Connect to the server over TCP. The protocol is line-oriented: every request and every response is terminated by a newline character (`\n`). Commands are case-sensitive and must be lowercase.


## Request format

```
COMMAND path [payload]
```

- `COMMAND` - one of the commands listed below
- `path` - collection name, or `collection/document` for a single document
- `payload` - optional JSON object, on the same line, separated by a single space

### Path rules

- no leading slash: `players`, `players/7f3c2d1a-...`, never `/players`
- collection names and document ids must match `^[a-z0-9_-]{1,64}$`: lowercase letters, digits, `_` and `-`
- because of that rule, `Players` is not `players`: names are always lowercase, and collections must be created before being used
- `insert` takes a collection only, never a document id: the id is generated by the server


## Response format

Every response is a single line terminated by `\n`.

| Response | Meaning |
|---|---|
| `OK` | Command succeeded, no data to return |
| `OK <uuid>` | Document created; UUID of the new document |
| `OK {...}` | Single document returned as JSON |
| `OK [...]` | List of documents returned as JSON array |
| `ERROR NOT_FOUND` | Document or collection does not exist |
| `ERROR ALREADY_EXISTS` | Collection already exists |
| `ERROR COLLECTION_NOT_FOUND` | Target collection does not exist |
| `ERROR INVALID_JSON` | Malformed JSON payload |
| `ERROR MISSING_ARGUMENT` | Missing required argument |
| `ERROR INVALID_PATH` | Invalid name, or arguments that do not belong to the command |
| `ERROR INVALID METHOD <name>` | Unknown command |

The payload after `OK ` is always valid JSON, so a client can parse everything from index 3 onward.


## Commands

### `create` - create a collection

```
create collection
```

Creates a new empty collection. Returns `ERROR ALREADY_EXISTS` if a collection with that name is already present.

**Example:**
```
create players
OK
```


### `drop` - delete a collection

```
drop collection
```

Deletes the collection and all its documents. Returns `ERROR NOT_FOUND` if the collection does not exist.

**Example:**
```
drop players
OK
```


### `insert` - insert a document

```
insert collection {"key": "value", ...}
```

Inserts a new document into the collection. The server generates a UUID v4 as the document ID and returns it. The payload must be a valid JSON object: an array, a number or a string are rejected with `ERROR INVALID_JSON`.

**Example:**
```
insert players {"username": "alice", "score": 0}
OK 7f3c2d1a-84b5-4e29-a3f1-0c9d2e5b6f78
```


### `read` - read documents

**Read all documents in a collection:**
```
read collection
```

**Read a single document by ID:**
```
read collection/id
```

**Read with a filter:**
```
read collection filter EXPRESSION
read collection EXPRESSION
```

Returns `OK [...]` for collection reads and `OK {...}` for single-document reads. A filter can also be applied to a single document: if it does not match, the response is `OK []`. Returns `ERROR NOT_FOUND` or `ERROR COLLECTION_NOT_FOUND` if the document or collection does not exist.

**The order of the documents in the response is not defined.** The server returns them in whatever order the internal map yields, so a client that needs a specific order has to sort the array itself.

**Examples:**
```
read players
OK [{"username": "alice", "score": 0}, ...]

read players/7f3c2d1a-84b5-4e29-a3f1-0c9d2e5b6f78
OK {"username": "alice", "score": 0}

read players filter score > 10
OK [{"username": "bob", "score": 42}]

read players balance>50
OK [{"username": "alice", "balance": 100}]
```


### `write` - partially update a document

```
write collection/id {"key": "new_value"}
```

Performs a partial update (patch) on the specified document. Only the properties included in the payload are updated; all other properties are left unchanged. This is not a full replace. Nested objects and arrays are supported in the payload.

**Example:**
```
write players/7f3c2d1a-84b5-4e29-a3f1-0c9d2e5b6f78 {"score": 15}
OK
```

The document after the operation:
```json
{"username": "alice", "score": 15}
```


### `delete` - delete a document

```
delete collection/id
```

Returns `ERROR NOT_FOUND` or `ERROR COLLECTION_NOT_FOUND` if the document or collection does not exist. This command does not accept a filter.

**Example:**
```
delete players/7f3c2d1a-84b5-4e29-a3f1-0c9d2e5b6f78
OK
```


## Filter expressions

Filters apply to the top-level properties of documents only. Nested properties are not supported.

### Comparison operators

| Operator | Meaning |
|---|---|
| `=` | equal |
| `!=` | not equal |
| `>` | greater than |
| `<` | less than |
| `>=` | greater than or equal |
| `<=` | less than or equal |

- the `filter` keyword is optional
- spaces around the operator are allowed: `score > 10` and `score>10` are the same filter
- `=` and `!=` are case-insensitive and always compare as text
- `<`, `<=`, `>`, `>=` compare numerically when both values are numbers, otherwise as text
- `true`, `false` and arrays are compared as their JSON text, so `playerIds=alice` never matches anything
- documents that do not have the property are never returned
- conditions cannot be combined: there is no `AND` and no `OR`

**Examples:**
```
read players filter score > 10
read players balance >= 100
read players username = alice
```
